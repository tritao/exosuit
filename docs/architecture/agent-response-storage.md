# Captured agent response storage

The agent response archive is a separately versioned extension to workspace schema version 8. It stores only captured UTF-8 response bytes associated with a provider, session, turn and item, retaining the partial flag. Each entry is limited to 256 KiB; the workspace retains at most 128 entries and 4 MiB, evicting the oldest entries first. Deleting a session deletes its response archive in the same transaction. Missing or evicted entries are unavailable; their contents must not be reconstructed from a truncated preview.

Opening a version 8 database initializes the extension transactionally without changing the core schema version. Older version 8 daemons can open the database and ignore the extension. Because they do not remove associated responses when deleting a session, the new daemon prunes orphaned response rows on its next open. The new daemon rejects unknown extension versions or unexpected extension table definitions instead of treating them as compatible. Exact response digests bind recovered content to its saved message preview. Tests use isolated databases.


Claude and Pi integrate this extension through optional `WorkspaceAgentContentPersistence`; other persistence implementations keep their existing required interface. Captured terminal messages retain a digest of their bounded UTF-8 source plus the partial flag in the small replay. Recovery validates exact scope and digest before issuing a content token. A corrected response with the same preview prefix cannot load an older stored body. Full-message cache eviction can rehydrate the verified source while preserving the published token; unverified legacy previews remain previews. Current memory remains usable if archival writes fail, with an explicit history error.
