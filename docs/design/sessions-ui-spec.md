# Sessions UI refinement

## Product contract

Sessions are first-class IDE documents backed by the existing workspace agent service. Codex, Claude, Pi and the built-in agent use the same visual language, with controls driven by provider capabilities. Terminals, editor documents, workspace groups, remote workspaces and source control retain their existing ownership and behavior. Work is isolated on branch `ui-exploration`.

The desired experience combines the readable conversation and compact composer of T3 Code with the quiet hierarchy of Hermes Desktop. The code references and commits are recorded in [the reference research](chat-ui-reference-research.md). Exosuit remains an IDE: opening a file or reviewing changes uses its established editor and Source Control surfaces.

The visual direction includes crisp, defined borders, restrained corner rounding and subtle contact/ambient shadows. A palette change alone does not meet the quality bar. Use a recessed application frame, a defined workspace surface, quiet navigation controls and a composed, elevated input area; inspect real native pixels in both themes.

## Conversation

- Give assistant prose a comfortable reading measure. Distinguish user messages with a subtle surface, role labels and consistent spacing. Keep provider identity and readable connection/turn status in the header.
- Render streaming Markdown without losing incomplete content. Keep heading, quote, list and paragraph boundaries even without blank separators; match complete inline backtick runs and preserve unfinished delimiters. Support headings, lists, bold/italic emphasis, inline code, explicit links, fenced code, quotes and tables using native views. Emphasis uses real isolated system font faces, with readable regular-text fallback when unavailable or beyond rendering limits; never mutate editor fonts. Preserve literal content where typography cannot faithfully represent unsupported Markdown.
- Put language and copy above code. Preserve exact source on copy, syntax highlighting, native selection and horizontal scrolling for wide code and tables. Offer separate whole-message copy with confirmation.
- Keep command and reasoning disclosures collapsed initially; show supplied details on request. Expanded command/tool output is selectable monospace in a bounded two-axis viewport with verbatim copy and a partial indicator. Keep command status visible independently of its ellipsized target and retain keyboard-accessible disclosure. Display actual file-change patches with numbered hunk rows, addition/removal tint, per-file disclosure and copy/open actions. Preserve source fidelity and label truncated data.
- Associate edits with files from optional provider-reported metadata. Codex reports bounded slices into its existing patch payload, keeping legacy fields available without duplicating patch data on the wire. Legacy unattributed output stays unattributed. Counts describe observed patch lines, not a net Git checkpoint.
- Recognize standalone and inline Markdown images without consuming surrounding prose or interpreting code spans. Offer explicit native previews for authorized local/remote workspace PNG/JPEG/GIF and bounded raster data URLs. Remote reads pin revision and validate each 32 KiB chunk; never resolve remote host paths locally. Chat previews fit within 512 pixels, while remote editor tabs retain original dimensions up to 4096 pixels and a shared 128 MiB texture budget. Preserve alt text and explanatory fallbacks. External images do not fetch implicitly.
- Completed HTML/SVG and substantial code fences have compact source artifact cards. Preserve original line endings and final newlines for copy. Incomplete fences remain visible inline while streaming. On Windows with a suitable WebView2 runtime, HTML and SVG can open in an isolated static preview, bounded to 512 KiB of source; setup or policy failures leave source available. Scripts, navigation and external resources are disabled. SVG also has a bounded native preview for supported shapes and paths, with an explanatory fallback for unsupported SVG.
- Native Codex image-view and image-generation activities expose explicit previews/open actions only for validated workspace paths, using the owning host file service. Preserve status, revised prompt/failure and raw details; report missing/outside-workspace assets explicitly. Native plan items use Markdown with exact source copy, bounded full-source retrieval and authoritative completed text replacing streamed deltas.
- For Codex, Claude and Pi, negotiate full assistant-message retrieval separately from bounded activity previews. Automatically load the latest completed truncated response, offer explicit loading for older responses, and reject changed or unavailable snapshots. Transfer at most 24 KiB per chunk and retain at most 256 KiB per message; label a larger response as partial. Copy the displayed full response when available and identify preview copies. Claude/Pi persist captured terminal assistant response bytes in a bounded optional SQLite extension. Saved response digests bind restored previews to the exact source version before regenerating content tokens; legacy, evicted or mismatched sources remain unavailable.
- Pi successful edit events can expose an actual provider-reported unified patch while retaining the original tool input and output; do not treat display-oriented numbered diffs as patches. Claude tool completions retain their reported arguments and truncation state.
- Group pending requests after the conversation. Pi renders exact native selection options and confirmation labels. Complete bounded Codex/Claude questions use native single/multiple choices, descriptions and custom answers; raw details stay behind disclosure, answers remain independent of the composer and server validation checks the retained request. Legacy requests retain their prompt-answer fallback. Secret fields require a protected-input client; Claude custom multiple answers cannot contain its native comma separator. Preserve reviewability, retry, queue/steer and recovery behavior.
- Bound displayed pending requests to eight and an 8 KiB encoded page. Show the waiting count and reveal further requests as earlier ones resolve. Oversized requests retain their identity and an unreviewable fallback rather than implying that clipped data can be approved. New services separately negotiate immutable chunked snapshots for complete views larger than a relay frame.
- Keep the composer visible when space permits; scroll the whole document when the dock becomes too short. New output follows the transcript only while the reader is at its bottom. Retain the draft and model/effort choices through ordinary renders.

## Remote snapshot contract

- Negotiate snapshot support in the agent catalog; retain the legacy ACTION path for older services. Execute actions once and acknowledge a successful response before loading the resulting view. A failed view fetch must never imply that the action should be repeated.
- Preserve the actual activity, models, commands, pending inputs, requests and history cursor in one immutable encoded view. Transfer at most 24 KiB per chunk, validate scope/token/total/offset and fence connection, service-generation, selection and disposal changes before publishing it.
- Bound an individual snapshot to 4 MiB, four stored snapshots and 8 MiB per connection, with 30-second idle and 120-second absolute expiry. Release storage on completion, disconnection and service disposal. Report explicit capacity/expiry/oversize errors without silently trimming view fields.
- Keep pending requests discoverable above the transcript. Review request scrolls to the request heading on explicit pointer or keyboard activation; it does not move a reader automatically.

## Incremental transcript history

Publish the latest page immediately. Load earlier messages is explicit and fetches one older page per activation; preserve the first visible message position after prepending. Show loading, retry, unavailable-history and reset states without replacing the composer. Returning to latest restores the separately retained current view.

The client reading window holds at most 256 activity items and 4 MiB of encoded item data. Keep older reading context stable while live activity arrives; if the ranges disconnect or retention would evict that context, show that the reader is detached and offer Return to latest. Reconcile retained in-progress items through continuation reads so completion outside the latest eight items cannot remain stale indefinitely. Reject cursor cycles and stale connection, selection or history generations. An epoch change requires an explicit reset rather than joining unrelated ranges.

Codex attachment reads one native page of eight items. Older pages are fetched on demand, normalized into an eight-page refetchable cache, with full-message retrieval available while its source is retained. Public cursors preserve the legacy two-part decreasing numeric shape. Native tokens stay in a session/epoch-scoped table retaining the first continuation and newest 127 handles; expired intermediate handles fail explicitly, while forward traversal can continue. Restarting from the beginning reconstructs an expired path. Local Codex live entries are still unbounded; this cache policy does not establish bounded lifetime host memory.

Claude, Pi and AgentKit retain bounded live/replayed activity. Known eviction is labeled; an older replay without that flag does not prove complete native history. Do not imply that unavailable history or expired full-message source has been recovered.

## Composer and IDE navigation

- A lightly raised multiline composer gives the draft a spacious, quiet surface. Model, reasoning and permissions use compact text controls with chevrons rather than a row of boxed fields; attachment and send use accessible icon actions. Put workspace/worktree context in a separate strip below the main input. Keep the edge crisp with restrained rounding and subtle elevation. Preserve Enter, keypad Enter, Shift+Enter, command completion and provider-specific send/queue/steer handling.
- Keep Permissions visibly labeled alongside its current profile. Use consistent decorative line icons for model, reasoning, permissions, attachments, worktree and branch, preserving accessible names and selected values. The footer exposes separate worktree/directory and branch controls: creating a worktree or choosing an existing scoped session directory starts a new same-provider session; the current native thread keeps its working directory. Branch selection uses the existing SCM picker and rechecks the owning session, repository and workspace before applying a change. Disabled or unavailable capabilities stay explicit.
- Show the actual session working directory and known branch. Keep Permissions, Files and Review changes immediately available and group secondary worktree/commit/GitHub/PR actions in a compact keyboard-accessible Git menu, revalidating target and capability on activation. Offer Files and Review changes as navigation actions; review means current workspace changes, not turn-attributed checkpoints.
- Explicit Markdown file links open in Exosuit at optional `:line:column` or `#Lline` locations. Resolve relative paths against the session working directory. Validate workspace identity on activation and asynchronous completion. Remote host paths use workspace file RPC, never the local OS shell.
- External HTTP(S)/mailto links open only on activation. Unsupported schemes remain literal. Local paths never go to the OS shell. Out-of-workspace file links report an actionable error.
- Commit changes selects the session's nearest writable Git repository and focuses the existing Source Control draft editor. Commit, branch, push and other Git mutations retain existing review and permission flows; opening the editor never submits a commit.
- Include up to two bounded workspace text snapshots through the owning host's file service. Label them as text context, show removal and read errors, and preserve edits made while a submission is awaiting acknowledgement.
- Codex, Claude and Pi sent images have optional opaque session/turn/item-scoped identities, with explicit native Preview and Open image actions. Associate only managed image paths observed in actual native user messages; unknown/recovered external paths remain unavailable. Retain at most 32 archived images / 64 MiB across the workspace, evict oldest unpinned images, preserve active leases and recover bindings across service restart. Reads require workspace READ permission and use bounded 24 KiB chunks; opened images use capped in-memory tabs and are excluded from local layout restore.
- Codex, Claude and Pi negotiate native image input separately from text context. Choose a local image or paste an image-only Windows clipboard payload; ordinary text paste retains its normal behavior. Upload bounded chunks to private host staging and send opaque session-scoped handles; the provider resolves these to host-local image input. Show bounded in-memory draft thumbnails and upload/failure/removal states, dispose preview resources on removal, acknowledgement or unmount, and retain unsent draft content. Pi supports native base64 image input for immediate prompts, queue and steer, with durable opaque references in its outbox and no base64 in replay records. Claude supports immediate image prompts through its verified installed stream-JSON schema, with bounded image blocks, private durable staging and uncertain-delivery protection; its provider does not advertise queue or steer.
- A negotiated Git worktree operation creates a new branch and a new child checkout inside the workspace. Start the integrated session only after its group is bound to the resulting directory. Preserve the original checkout and report the recoverable destination if later group/session creation fails.
- GitHub actions use an authoritative host-side origin query, allowlisted canonical URLs and explicit activation. Revalidate before opening the repository or a comparison/PR creation page for the current named branch. Opening that page does not push a branch or submit a PR.

## Theme workstream

Both light and dark modes share semantic colors, geometry and interaction hierarchy. Dark is the first visual evaluation target. Use neutral, layered surfaces; readable secondary text; crisp borders; a consistent blue focus/action accent; and compact tab labels. Selected tabs connect visually to the editor canvas. Workspace and selection surfaces use native geometry shadows; the composer uses a defined one-pixel edge and raised native box. Respect explicit appearance settings and preserve syntax/diagnostic meaning. Details are in [theme polish](theme-polish.md).

## Follow-on capabilities requiring transport/native changes

These are part of the intended complete experience, but must be implemented end to end before exposing their controls:

1. **Broader input and history:** Codex/Claude/Pi support bounded image input; Pi also supports durable queued/steered image references. Broader attachment types remain unsupported. Draft thumbnails are temporary. Codex/Claude/Pi sent-image previews use a bounded durable scoped archive; broader attachment types and longer retention require a separate archive policy. Non-Windows image clipboard support remains to be implemented. Passing client-local filenames as though they were remote attachments is incorrect.
2. **Broader response history:** Codex recovers native paged source; Claude and Pi now recover captured terminal response bytes for their retained replay through a bounded durable archive (256 KiB/message, 128 messages/4 MiB per workspace). Legacy snippets and evicted or digest-mismatched sources remain unavailable. General native-history recovery beyond the replay window and unlimited archival retention remain separate work.
3. **Broader artifacts:** Windows static HTML/SVG preview is intentionally inert and availability-dependent; it does not implement arbitrary interactive web applications. The native SVG subset rejects unsupported features. [Renderer contracts](renderer-contracts.md) records the actual boundary and platform requirements.
4. **PR submission:** opening an authoritative GitHub comparison page is supported separately from submitting a PR. Actual submission needs a supported authenticated review/network workflow.

These are explicit remaining capabilities, not implied by the visual implementation. The local-source audit identifies the exact current boundaries.

## Acceptance and regression checks

- Build the graphical app and agent from this isolated worktree with independent dependency/build outputs.
- Native layout checks cover code header order, inline spacing, wrapping, quote/table rendering and keyboard-accessible links.
- Presentation checks cover both themes and multiple providers, empty/streaming/request states, draft submission, model/effort controls, and narrow/wide layouts.
- Desktop layout and native capture checks include 1920, 2560 and 5120 pixel widths alongside 320 and 1000. Keep the transcript and composer centered at a readable measure, align trailing actions and footer selectors, and avoid stretching controls across an ultrawide screen.
- Pure link tests cover Windows/POSIX paths, relative navigation, location suffixes, nested URL parentheses, unsupported schemes and incomplete streaming syntax.
- Existing theme tests verify control state colors, selected-tab canvas, readable contrast and editor/default consistency.
- Run provider/state tests where the platform supports them. Linux Xvfb scenarios are not evidence of Windows validation unless actually run on a Linux host.
- Visual QA must inspect the real native UI; a successful build or token contrast calculation alone does not establish production polish.
