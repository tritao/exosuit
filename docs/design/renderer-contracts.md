## Inline edit diffs and changed-file summaries

Hermes normalizes a tool call as a part with `type`, `toolName`, `args`, `result` and metadata. `apps/desktop/src/components/assistant-ui/tool/fallback-model/index.ts:854` reads nonempty `inline_diff` or `diff` from the parsed result, strips ANSI and a review heading; `fileEditPath` (`:69`) selects `path`, `file`, or `filepath` from args, then result including `resolved_path`, then an HTML-path fallback from the diff. `countDiffLineStats` (`:53`) counts leading `+`/`-` lines excluding `+++`/`---` headers. `tool/fallback.tsx:425` keys disclosure to the call, defaults an available diff open, and suppresses normal raw detail when the diff is shown; hidden-diff mode retains counts, and failed edits retain their error. Expanded content mounts `FileDiffPanel` (`:708`); copy uses the full unclamped payload (`:540`).

`apps/desktop/src/components/chat/diff-lines.tsx` parses unified hunk headers into old/new starting numbers and lines `{kind: add | remove | context, text, oldNo?, newNo?}`. It strips recognized preamble and +/- marker for display while preserving remaining indentation, inserts separators between hunks, and falls back to color-only text for unexpected non-hunk input. It layers add/remove background and a narrow edge over optional filename-language highlighting; the inline box has a bounded vertical height and horizontal scroll, and oversized/unavailable highlighting falls back to plain colored lines. The full-file preview has a separate current-file-based mapping. These display transformations do not replace the raw diff used for copying.

Hermes `thread/changed-files.ts:deriveChangedFiles` filters tool-call parts to file-edit tools with actual inline diff and path, folds by exact reported path in first-touched order, and sums +/- over edits. Its `ChangedFilesCard` shows filename, +/- and a Review action, with a bounded roughly five-row scroll area; each row opens review for its path and session cwd (`thread/changed-files-card.tsx`). The assistant-message component shows the card after the turn settles (`thread/assistant-message.tsx:510`). Those counts are the **sum of edit events**, not necessarily the net repository diff; absence of a diff is not proof a file was unchanged.

T3's `apps/web/src/components/chat/ChangedFilesTree.tsx` receives `{runId, files: TurnDiffFileChange[]}` from a checkpoint summary (`apps/web/src/types.ts:100`); it renders file count and aggregate +/- plus expandable directory tree and individual file counts. Rows open `onOpenTurnDiff(runId, path)` and the header opens the run's full diff; it virtualizes beyond 250 rows. `DiffPanel.tsx:231` resolves the thread worktree before the project root and `:274–360` separates turn checkpoint, working-tree and branch queries. This is a different contract from Hermes's tool-event summary.

**Exosuit path:** render an inline diff only from an identifiable, actual diff payload, preserving original bytes for copy and making raw fallback visible if parsing fails. Present +/- and path when reliably available; use line color *and* markers/accessibility labels, bounded scroll and syntax fallback. A turn summary can fold observed successful edits but must be labeled as such; only advertise a net turn/checkpoint diff if the service supplies trustworthy snapshots and run attribution. Do not invent file counts from unstructured prose or silently use the current Git state as a past turn.

## Markdown, code blocks and render dispatch

T3 `apps/web/src/components/ChatMarkdown.tsx:925` dispatches Markdown block/inline elements to separate components; `:1511` extracts fenced code and language, sends it to a themed Shiki renderer with error fallback to plain `<pre>`, and delegates a `mermaid` fence to a diagram component. It gates shell execution on a closed, non-streaming fence. `chat/MarkdownCodeBlock.tsx` owns the common frame, language/title and exact code-copy action. Tables and details have dedicated components (`ChatMarkdown.tsx:1502`).

Hermes `apps/desktop/src/components/assistant-ui/markdown-text.tsx:625` keeps fence parsing active during streaming while deferring expensive highlighting. At `:747` its fence callback first calls `detectArtifact` unless preview-only or scratchpad; detected content becomes an `ArtifactCard`, otherwise the normal rich-fence/code path handles it. `lib/artifact-detect.ts` promotes HTML documents at 160 characters or HTML fragments at 1,200; standalone SVG at 2,000; code at 3,000 characters or 48 lines; it excludes diff, shell output, text, Markdown and Mermaid from code promotion. These are heuristics, not semantic guarantees.

`assistant-ui/artifact-card.tsx` shows kind/title and streamed line count while incomplete, registers completed content in a session registry, deduplicates by content hash, and opens on click at the clicked version. `app/chat/right-rail/preview-artifact.tsx` retrieves content by artifact ID, offers rendered/source modes for HTML and SVG, source-only for code, version stepping, copy and download. An HTML fragment is wrapped in a document; full documents pass through. The source view and copy retain artifact content independently from its rendered view.

**Exosuit path:** keep current native code block, extend block types and preserve a raw representation for copy. A compact explicit artifact card and source view can be built before live rendering; do not let an unclosed or streaming block create a durable artifact prematurely. Exosuit's existing `CodexMarkdown` intentionally does not execute raw HTML.

## HTML and SVG preview boundaries

Hermes `preview-artifact.tsx:ArtifactLiveView` uses `iframe sandbox="allow-scripts"` and `srcDoc` for HTML, without `allow-same-origin`, and uses DOMPurify's SVG and SVG-filter profile before inserting SVG. `assistant-ui/embeds/svg-embed.tsx` uses the same sanitization and caps dimensions. Its sandbox allows scripts; the source does not establish that all network/subresources are blocked. T3 `apps/web/src/components/files/BrowserDocumentFrame.tsx` has an opaque-origin iframe: ordinary files allow scripts, forms, popups and downloads, while its specialized `HtmlRenderDocument` allows scripts and forms but omits same-origin; it validates frame message source and permits only selected visual shortcuts, and checks user activation for link/image messages. These are browser-specific boundaries, not automatically provided by NativeKit WebView.

**Exosuit path:** source-only initially; if adding live preview, define and test the actual native backend's isolation and network/file/navigation policy explicitly. A navigation callback alone does not constrain scripts or subresource requests. Use a bounded safe SVG renderer/sanitizer with no external resources; retain a source toggle and exact copy.

## Images and attached file previews

Hermes `tool/fallback-model/index.ts:805` searches result fields `image_url`, `url`, `path`, `image_path`, then args; accepts `data:image/`, extension-qualified HTTP(S), or recognized local image path. `fallback.tsx:690` passes the result through `MarkdownImage`; the source comments say filesystem images resolve through an authenticated media pipeline. A URL or data image is presentation data, not proof that the provider's input accepts attachments.

T3 `ChatMarkdown.tsx:1450` distinguishes direct image/video URLs from workspace-file image assets; the latter carries environment, thread and path into `ChatMarkdownAssetImage`. `chat/ChatMarkdownMedia.tsx` obtains scoped asset URLs and renders fallback/error states with original Markdown copy. `files/AttachmentFilePreview.tsx` dispatches by name/MIME/size, creates and revokes Blob URLs for local files, requests renewable authorized URLs for remote assets, and exposes rendered/source modes for Markdown, HTML, Mermaid and tables. It shows loading and errors and limits large text previews. `media/AttachmentImage.tsx` falls back to lazy HEIC/TIFF decoding and revokes the generated object URL.

**Exosuit path:** use typed asset identity, session/workspace scope and bounded bytes; retain loading, unsupported and error states and dispose decoded resources. Existing `UiImageTab` is local raster-file-only, while `ClipboardService` and agent action protocol are text-only. Adding image output display, image input upload, and SVG/HTML rendering are separate transport and security tasks; implement only capabilities supported end to end.
